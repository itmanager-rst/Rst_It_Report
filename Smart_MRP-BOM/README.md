# Smart MRP & BOM สูตรการผลิต

ระบบ MRP/วางแผนการผลิตสำหรับสายผลิตอุปกรณ์ต่อพ่วงรถแทรกเตอร์ (RST ASIA) — เป็นเว็บแอปไฟล์เดียว (`index.html`) ไม่ต้องมีเซิร์ฟเวอร์ของตัวเอง เก็บข้อมูลไว้ในเบราว์เซอร์ผู้ใช้ และ (ถ้าตั้งค่า) ซิงค์ขึ้น Google Sheet กลางให้ทุกคนในทีมเห็นข้อมูลตรงกัน พร้อมโครงสร้างสำหรับเชื่อมต่อ ECOUNT API

---

## ภาพรวมสถาปัตยกรรม

```
เบราว์เซอร์ผู้ใช้ (index.html บน GitHub Pages)
        │  fetch (GET ดึงข้อมูล / POST ส่งข้อมูล, บันทึก PR เข้า Ecount)
        ▼
Google Apps Script Web App (apps-script/Code.gs)
        │
        ├── อ่าน/เขียน Google Sheet  ← ฐานข้อมูลกลางของระบบ (ทุกตารางเป็นชีตแยก)
        │
        └── UrlFetchApp → ECOUNT OAPI  (credential เก็บใน Script Properties ฝั่งนี้เท่านั้น)
```

- **หน้าเว็บ (`index.html`)** ไม่เก็บรหัสผ่าน/คีย์ลับใดๆ เพราะเมื่อ publish บน GitHub Pages แล้วใครก็เปิดดู source ได้ ทุกอย่างที่ต้องปิดเป็นความลับ (โดยเฉพาะ ECOUNT API key) จึงต้องอยู่ใน Apps Script (Script Properties) ซึ่งรันฝั่งเซิร์ฟเวอร์ของ Google เท่านั้น
- ตัว URL ของ Apps Script Web App ตัวเดียว ทำหน้าที่ทั้งเป็น "ฐานข้อมูล" (อ่าน/เขียน Google Sheet) และเป็น "ตัวกลาง (proxy)" ไปยัง ECOUNT API

## ส่วนที่ 1 — ตั้งค่า Google Sheet เป็นฐานข้อมูล

1. สร้าง Google Sheet ใหม่ (ชื่ออะไรก็ได้ เช่น `Smart MRP & BOM Database`)
2. เมนู **Extensions (ส่วนขยาย) > Apps Script**
3. ลบโค้ดเริ่มต้นทั้งหมดในไฟล์ `Code.gs` แล้ววางโค้ดจากไฟล์ [`apps-script/Code.gs`](apps-script/Code.gs) ในโฟลเดอร์นี้แทน
4. กด **Save** (ไอคอนแผ่นดิสก์)
5. กด **Deploy > New deployment**
   - Select type: **Web app**
   - Description: ใส่ได้ตามสะดวก เช่น `smart-mrp-bom-backend`
   - Execute as: **Me** (บัญชีของผู้ดูแลระบบ)
   - Who has access: **Anyone** (จำเป็น เพื่อให้หน้าเว็บที่ผู้ใช้ทุกคนเปิดเรียก API ได้ — ตัวสคริปต์เองไม่ได้เปิดให้แก้ไข Sheet โดยตรงจากภายนอก มีแต่ผ่าน API ที่กำหนดไว้เท่านั้น)
6. กด **Deploy** แล้วอนุญาตสิทธิ์ (Authorize access) ตามที่ระบบขอ
7. คัดลอก **Web app URL** ที่ได้ (รูปแบบ `https://script.google.com/macros/s/xxxxxxxx/exec`)
8. เปิดเว็บแอป (`index.html`) → เมนู **ตั้งค่า > การเชื่อมต่อ** → วาง URL ในช่อง "Apps Script Web App URL" → กด **บันทึก URL** → กด **ทดสอบการเชื่อมต่อ** เพื่อยืนยันว่าเชื่อมได้
9. กด **ส่งข้อมูลขึ้น Sheet** ครั้งแรก เพื่อสร้างข้อมูลเริ่มต้นในชีตจากข้อมูลตัวอย่าง/ข้อมูลปัจจุบันในเครื่อง
10. เปิดติ๊ก "ซิงค์ขึ้น Sheet อัตโนมัติ" หากต้องการให้ทุกการบันทึกในระบบซิงค์ขึ้น Sheet ทันที (ไม่ติ๊กก็ยังใช้งานได้ปกติ แค่ต้องกด "ส่งข้อมูลขึ้น Sheet" เองเป็นระยะ)

**เมื่อทีมงานคนอื่นเปิดเว็บแอปนี้แล้วนำ URL เดียวกันไปตั้งค่า** ทุกคนจะอ่าน/เขียนข้อมูลชุดเดียวกันบน Google Sheet — กด **ดึงข้อมูลจาก Sheet** เพื่อรับข้อมูลล่าสุดจากเพื่อนร่วมทีม

> ข้อควรทราบ: การซิงค์นี้เป็นแบบ "เขียนทับทั้งชุด" (คนละกลไกกับสเปรดชีตแบบ real-time ของ Google Sheets ทั่วไป) เหมาะกับทีมขนาดเล็ก-กลางที่ไม่ได้บันทึกพร้อมกันในวินาทีเดียวกันบ่อยๆ ถ้าต้องรองรับผู้ใช้พร้อมกันจำนวนมาก ควรพัฒนาเป็น API แบบ per-record ในอนาคต

### โครงสร้างชีตที่ระบบจะสร้างให้อัตโนมัติ

| ชีต | เก็บข้อมูล |
|---|---|
| Materials | วัตถุดิบ + สต็อก + ราคา |
| Products | สินค้า/สูตรผลิตหลัก |
| BOM | รายการวัตถุดิบต่อสูตรผลิต (แยกจาก Products เพื่อให้ 1 สินค้ามีได้หลายบรรทัด) |
| WorkOrders | ใบสั่งผลิต |
| DailyLogs | บันทึกผลผลิตรายวัน |
| PurchaseRequests / PRItems | ใบขอซื้อ และรายการในใบขอซื้อ |
| StockLog | ประวัติการเบิก/ปรับสต็อก |
| Sales | ประวัติการขาย |
| Lists | หมวดหมู่สินค้า/วัตถุดิบ/แผนก/ขั้นตอนผลิต (จากหน้าตั้งค่า) |
| Settings | ค่าตั้งค่าอื่นๆ เช่น เลขรันต่างๆ |

ดูข้อมูลได้ตรงๆ ใน Google Sheet เลย เหมาะกับการทำรายงานเพิ่มเติม/เชื่อม Pivot table/Looker Studio ต่อได้ในอนาคต

## ส่วนที่ 2 — เผยแพร่ระบบผ่าน GitHub Pages ให้ทีมใช้งาน

1. สร้าง repository ใหม่บน GitHub (public หรือ private ก็ได้ — ถ้าต้องการให้ GitHub Pages ใช้ได้ฟรีบน repo private ต้องมีแผน GitHub ที่รองรับ Pages สำหรับ private repo)
2. อัปโหลดไฟล์ในโฟลเดอร์นี้ทั้งหมด (`index.html`, `apps-script/`, `README.md`) ขึ้น repo โดยให้ `index.html` อยู่ที่ราก (root) ของ repo หรือของโฟลเดอร์ที่จะตั้งเป็น Pages source

   ตัวอย่างคำสั่ง (รันจากในโฟลเดอร์นี้ หลังสร้าง repo บน GitHub แล้ว):
   ```bash
   git init
   git add .
   git commit -m "Initial commit: Smart MRP & BOM สูตรการผลิต"
   git branch -M main
   git remote add origin https://github.com/<ชื่อบัญชีของท่าน>/<ชื่อ-repo>.git
   git push -u origin main
   ```
3. ใน repo บน GitHub ไปที่ **Settings > Pages**
4. ที่ **Build and deployment > Source** เลือก **Deploy from a branch**
5. เลือก branch `main` และโฟลเดอร์ `/ (root)` แล้วกด **Save**
6. รอสักครู่ (ปกติ 1-2 นาที) แล้ว GitHub จะแสดง URL ของเว็บ เช่น `https://<ชื่อบัญชี>.github.io/<ชื่อ-repo>/`
7. ส่งลิงก์นี้ให้ทุกคนที่เกี่ยวข้องเปิดใช้งานผ่านเบราว์เซอร์ได้ทันที ไม่ต้องติดตั้งอะไรเพิ่ม

### อัปเดตเว็บในอนาคต
แก้ไข `index.html` แล้ว `git add . && git commit -m "..." && git push` — GitHub Pages จะอัปเดตให้อัตโนมัติภายในไม่กี่นาที

### ข้อควรระวังเรื่องความปลอดภัย
GitHub Pages เป็น **เว็บสาธารณะ** (แม้ตั้ง repo เป็น private ตัวเว็บที่ deploy ออกมาก็ยังเป็น URL ที่เข้าถึงได้จากใครก็ตามที่รู้ลิงก์ เว้นแต่จะใช้ฟีเจอร์จำกัดสิทธิ์เพิ่มเติมของ GitHub ซึ่งมีเงื่อนไขตามแผนองค์กร) จึงต้องไม่ใส่รหัสผ่าน, API key ของ ECOUNT, หรือข้อมูลลับใดๆ ลงในไฟล์ `index.html` โดยตรง — ค่าที่ผู้ใช้กรอกในหน้า "ตั้งค่า > การเชื่อมต่อ" (เช่น Web App URL) จะถูกเก็บไว้ใน `localStorage` ของเบราว์เซอร์แต่ละเครื่องเท่านั้น ไม่ได้ถูกฝังลงในซอร์สโค้ด

## ส่วนที่ 3 — เชื่อมต่อ ECOUNT API (โครงสร้างพร้อมใช้งาน)

โค้ดใน `apps-script/Code.gs` มีฟังก์ชันสำหรับเชื่อม ECOUNT OAPI ไว้แล้วตามรูปแบบมาตรฐานของ ECOUNT (ขอ Zone → Login ขอ SESSION_ID → เรียก API จริงด้วย SESSION_ID) แต่ **ยังไม่ได้ใส่ credential จริง** เพราะต้องได้รับจากบัญชี ECOUNT ของบริษัทท่านเอง

### วิธีเปิดใช้งานจริง
1. ในระบบ ECOUนT ของบริษัท ไปที่หน้า **Setup/시스템설정 > API 인증키 (API Certification Key)** เพื่อสร้าง/คัดลอก API Cert Key และตรวจสอบ `COM_CODE` (รหัสบริษัท) กับ `USER_ID` ที่มีสิทธิ์เรียก API
2. กลับไปที่ Apps Script (ตอนตั้งค่า Google Sheet ในส่วนที่ 1) → เมนู **Project Settings (การตั้งค่าโปรเจ็กต์) > Script Properties** → เพิ่มค่าดังนี้:

   | ชื่อ (Property) | ค่า |
   |---|---|
   | `ECOUNT_COM_CODE` | รหัสบริษัทใน ECOUNT |
   | `ECOUNT_USER_ID` | user id ที่มีสิทธิ์เรียก API |
   | `ECOUNT_API_CERT_KEY` | API Certification Key |
   | `ECOUNT_LAN_TYPE` | (ไม่บังคับ) `ko-KR` หรือ `en-US` |

3. ตรวจสอบ **ชื่อ endpoint สำหรับบันทึกใบขอซื้อ** จากเอกสาร API ของ ECOUNT (Setup > API 문서 ในระบบของบริษัทท่าน — ชื่อ/พารามิเตอร์ของ endpoint อาจต่างกันไปตามโมดูลที่บริษัทเปิดใช้งาน) แล้วแก้ค่าตัวแปร `ECOUNT_SAVE_PR_PATH` ที่ต้นไฟล์ `Code.gs` ให้ตรงกับ endpoint จริง จากนั้น Deploy ใหม่อีกครั้ง (Deploy > Manage deployments > แก้ไข deployment เดิม หรือสร้าง deployment ใหม่)
4. กลับมาที่หน้าเว็บ → **ตั้งค่า > การเชื่อมต่อ** → กด **ทดสอบเชื่อมต่อ ECOUNT** เพื่อยืนยันว่า Zone/Login ผ่าน
5. เมื่อเชื่อมต่อสำเร็จ ปุ่ม **"+ บันทึก PR เข้า Ecount"** ในหน้าใบขอซื้อจะส่งข้อมูลไป ECOUNT จริงโดยอัตโนมัติ (ถ้ายังไม่เชื่อมต่อ ปุ่มนี้จะยังทำงานแบบจำลองในเครื่องเหมือนเดิม ไม่กระทบการใช้งานปกติ)

## บทบาทผู้ใช้งาน (RBAC)

ระบบมีบทบาทตัวอย่างในตัว (ผู้จัดการโรงงาน / หัวหน้ากะ / เจ้าหน้าที่คลัง / ฝ่ายผลิต / ฝ่ายขาย) เลือกได้จากแถบด้านซ้ายของเว็บ ปัจจุบันเป็นการสลับบทบาทด้วยตนเอง (ยังไม่มีระบบล็อกอิน/สิทธิ์รายบุคคลจริง) เหมาะสำหรับสาธิตการทำงานตาม role ต่างๆ ก่อนพัฒนาระบบยืนยันตัวตนจริงในอนาคตหากต้องการ

## ข้อจำกัดที่ควรทราบ
- การซิงค์ Google Sheet เป็นแบบ pull/push ทั้งชุดข้อมูล ไม่ใช่ real-time collaborative editing — ถ้าสองคนบันทึกพร้อมกันโดยไม่ได้ดึงข้อมูลล่าสุดก่อน อาจมีข้อมูลของอีกฝ่ายถูกเขียนทับได้ แนะนำให้กด "ดึงข้อมูลจาก Sheet" ก่อนเริ่มทำงานทุกครั้ง
- ยังไม่มีระบบยืนยันตัวตน (login) จริง — ใครก็ตามที่มีลิงก์ GitHub Pages และ URL ของ Apps Script เชื่อมต่อฐานข้อมูลได้ หากต้องการจำกัดสิทธิ์เข้มงวดขึ้น ควรพิจารณาเพิ่มการยืนยันตัวตน (เช่น ผูกกับ Google Workspace ขององค์กร) ในโค้ด Apps Script
